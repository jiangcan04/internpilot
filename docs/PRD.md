# InternPilot 当前版本开发需求

大学生实习岗位匹配与求职管理智能体

版本 1.1    更新日期 2026年10月21日    使用对象 开发人员

## 一  项目目标与交付范围

面向寻找实习的大学生，覆盖不同专业和岗位方向。用户提供求职条件与个人材料，系统自动获取岗位并解释匹配依据；用户选择保留岗位、准备招呼语，投递后记录实际进度。

本版交付网页端，沿用现有工作台布局，接通一个招聘平台的岗位获取、模型分析与数据库保存。现有网页中的示例数据和本地规则用于交互参考，不能代替真实工具和模型调用。

### 主要流程

- 用户填写求职条件，提供简历文字；系统提取草稿，用户核对后选择新增或更新档案。

- 用户确认搜索，系统获取岗位、去重，并核对到岗条件、教育背景与经历证据。

- 用户查看结果和对话提问，自主选择入池或收藏；生成并编辑招呼语。

- 用户在原招聘平台手动投递，回工作台记录状态、日期和备注。

### 页面与主要职责

| 页面 | 主要内容 |
| --- | --- |
| 工作台 | 搜索入口、岗位数量、待跟进岗位与最近活动。 |
| 搜索结果 | 查看本批岗位、条件初筛、匹配依据、筛选和批量入池。 |
| 我的岗位池 | 全部跟进、只看收藏、已归档三个视图；支持手动添加和移出。 |
| 我的投递 | 查看和修改申请状态、实际投递日期与备注。 |
| 个人档案 | 基本信息与求职意向、简历材料、经历与能力三个页签。 |
| 岗位详情 | 左侧原文与分析，右侧当前岗位助手；包含沟通文案和申请记录。 |

### 账号约定

本版沿用原型的演示账号选择，支持进入、退出和切换账号，并明确显示“演示登录”。每个账号分别保存档案、岗位池、对话及投递记录。退出保留已保存数据，清空未提交输入和旧岗位引用；有运行任务或未保存修改时先提示。招聘平台登录与工作台账号分别处理。

## 二  个人档案与简历提取

档案是岗位匹配的共同依据。简历原文保留在“简历材料”，确认后的教育信息进入“基本信息与求职意向”，项目、实习和科研等进入“经历与能力”。三个入口使用同一份档案数据。

| 信息组 | 字段与要求 |
| --- | --- |
| 基本信息与求职意向 | 称呼、当前身份、目标方向、城市、每周可到岗天数、持续月数、最早到岗时间。称呼和搜索条件必填，开始时间不确定可标为待确认。 |
| 教育背景 | 每段分别记录学校、学历、在读或毕业状态、专业、所属学科、入学和毕业时间、985／211 标签、相关课程。学校、学历和状态必填；未知项留空，不推断。 |
| 简历材料 | 接受粘贴文字或读取 TXT、Markdown，文件不超过 10 MB。保留原文、材料名称和更新时间；本版不解析 PDF／Word。 |
| 经历与能力 | 名称、类型、本人职责、方法或工具、产出、关联技能、使用程度、来源和确认状态。名称与本人职责必填，其他内容可留空。 |

### 提取与保存流程

- 点击“提取并核对信息”，模型整理教育和经历草稿，暂不修改长期档案。

- 逐条展示来源原文、提取字段和目标模块，用户可以编辑、跳过或结束。

- 每条由用户选择“新增记录”或“更新已有记录”；更新时必须指定一条已有记录，并展示原内容供核对。

- 用户确认后才保存本条，同时保留原文片段与材料名称。结束核对只保留已经确认的条目。

例如，原档案已有 InternPilot 项目，新简历增加“接入岗位获取工具”。用户选择更新原项目，系统保留项目 ID 并更新内容，不再生成第二条项目。新简历未写出的旧经历继续保留。

### 手动补充与档案维护

教育与经历均可手动新增、编辑和删除。经历使用程度区分实际项目使用、课程练习、仅了解、暂未接触和待说明。模型不补造职责、成果或熟练程度。个人档案保留最近 8 次历史版本，可恢复；删除和更新支持撤回。

求职条件变化后重新检查规则；教育或经历变化后，相关旧分析标为“待更新”，用户可重新分析。档案修改不改变收藏、岗位池选择和实际投递状态，也不自动提高分数。

## 三  岗位获取与匹配分析

### 岗位获取

用户确认平台、岗位方向、城市、天数和实习时长后启动搜索。默认每批获取 10 个岗位，数量不足时返回实际结果。只展示已接入的平台；工具使用用户可访问的招聘页面，登录或验证受阻时暂停，由用户在招聘网页处理后继续。

搜索任务显示获取、整理、分析等阶段和已获取数量，支持停止及失败重试。手动添加原始 JD 和来源链接作为补充入口，不能替代自动获取功能。

每个岗位保存岗位名称、公司、来源平台、岗位 ID 或 URL、完整 JD、获取时间和条件字段。按平台加岗位 ID 或规范化 URL 去重；相同公司和岗位名只能提示疑似重复。重新获取不覆盖用户的收藏、文案、投递日期和备注。

### 匹配输入与输出

输入为当前 JD、确认后的教育记录、求职条件和相关经历。先核对明确条件，再由模型解释经历相关性。每条判断展示岗位原文、对应个人事实、匹配或缺口说明，以及下一步准备建议；没有证据时明确标为待确认。

| 结果分类 | 判断规则 |
| --- | --- |
| 建议了解 | 已知必备条件满足，存在相关个人事实，仍允许查看完整依据。 |
| 需要确认 | 个人信息不足、岗位要求不明、条件可协商或专业相关性不明确。 |
| 条件不符 | 岗位明确必备条件与个人已知条件冲突，显示具体冲突原因。 |

### 教育背景的判断规则

- 学历、在读状态、毕业届别、专业和学科均参与核对；本科与硕士分别保留，不能用一段学校信息覆盖另一段。

- 区分 JD 的必备要求与“优先”。985／211 仅对照 JD 明确提出的要求或偏好；没有要求时不自行加分或淘汰。

- 专业名称不同不直接等同不符合；结合相关课程、研究方向与项目说明相关性，不明确则待确认。

- “简历没写”不等于“不会”。能力相关不能抵消明确的到岗冲突。

### 结果展示与更新

默认展示建议了解和需要确认，条件不符可展开并由用户自行保留。搜索结果不自动入池。原型示例分数不作为真实结果；本版以分类和证据呈现，不要求实现百分制评分。JD 或档案变化后保留旧分析并提示待更新。

## 四  岗位详情与助手对话

### 原文引用与提问

岗位详情左侧保留阅读区，右侧保留一个助手输入区。选中文字后仅出现“向助手提问”。点击后将原文附到输入框，不立即发送，也不清空已有问题；引用可移除。用户发送后，消息记录当前岗位 ID 和引用来源。

切换岗位时清除未发送的旧引用，历史消息仍归属原岗位。模型回答使用当前岗位和相关档案，不能把其他岗位的要求混进来。查看与对话不自动修改档案或投递状态。

### 对话中的经历补充

助手发现证据不足时，可以询问使用情境、本人分工、方法和结果，并整理可编辑草稿。用户决定“仅用于本次对话”或“保存到个人档案”。

| 用户选择 | 保存行为 |
| --- | --- |
| 仅用于本次对话 | 记录在当前岗位对话中，不写入长期档案，不影响其他岗位。 |
| 保存到个人档案 | 用户核对后，选择新增经历或指定已有经历更新；与档案页共用记录，支持编辑和撤回。 |

岗位要求和助手推测只能作为追问依据，不能直接成为个人能力。本人确认表示认可自述，不代表系统完成第三方能力认证。

### 招呼语

输入当前 JD、用户确认的相关经历和到岗条件，生成简短可编辑的招呼语。缺少事实时省略或提示补充，不编造项目贡献、技能熟练程度和量化成绩。

- 支持生成、编辑、保存、复制和重新生成；有手工修改时，重新生成前提示是否替换。

- 生成、保存和复制均不发送给招聘方，也不自动标记为已投递。

- 提供原平台岗位链接。用户本人完成发送或申请，再回工作台确认投递状态；无有效链接时明确提示。

### 智能体的行动边界

系统自动执行岗位读取、去重、条件检查、证据分析和文案草拟。档案入档、岗位入池、外部投递和实际状态由用户决定。本版不包含简历撰写、自动发送、自动投递及 HR 回复监测。

## 五  岗位池与投递管理

搜索结果是系统找到的候选岗位；岗位池是用户明确选择跟进的岗位。收藏是池内的重点标记，不单独建立一级页面。

| 操作或视图 | 行为规则 |
| --- | --- |
| 加入岗位池 | 支持单个或批量选择。仅保存被选中的岗位；条件冲突时提示原因，用户确认后仍可加入。 |
| 收藏与取消收藏 | 搜索结果中收藏时同时入池；取消收藏只清除重点标记，不移出岗位池。 |
| 三个视图 | 全部跟进展示活跃岗位；只看收藏展示其中的收藏；已归档展示保留历史但暂不跟进的岗位。 |
| 手动添加 | 填写岗位名称、公司、完整 JD 和可选来源链接；未知条件留空。重复链接提示核对，不制造匹配分数。 |
| 移出与归档 | 没有投递历史时移出活跃岗位池，保留来源并可撤回；有投递历史时归档，保留日期、备注、文案和状态。 |
| 恢复归档 | 恢复为活跃跟进，原收藏标记和投递历史保留。 |

### 筛选与批量操作

支持按关键词、城市、方向、到岗天数、匹配分类和投递状态筛选。单个或批量操作仅作用于当前选中的岗位；切换视图或筛选后清除旧选择。清除筛选保留当前视图。页面数量与实际保存结果一致。

### 投递状态

状态为待投递、已投递、面试中、已结束、暂不考虑。状态由用户单个或批量修改，不由生成文案、打开链接或模型分析触发。批量操作先展示所选岗位数量。

选择已投递、面试中或已结束时，填写实际投递日期，可添加备注。批量备注留空时保留原备注。保存前确认所选状态，保存后刷新列表；标记实际投递时将岗位保留在岗位池。

### 撤回与记录保留

收藏、入池移出、归档、状态及档案变更支持撤回最近一次操作，只恢复本次涉及的字段。状态变更保存时间、前后值和备注；误操作撤回后，其他岗位和其后的有效记录不受影响。刷新或重新进入演示账号后可加载已保存数据。

## 六  数据保存与验收

前端负责展示、编辑和用户确认；后端负责岗位任务、模型调用和数据库保存；浏览器工具负责读取招聘页面。模型密钥放在后端。可在本机运行服务和获取工具，不依赖服务器自动继承用户浏览器的登录状态。

| 数据对象 | 至少保存的内容 |
| --- | --- |
| 账号与档案 | 账号 ID、求职条件、原始材料、教育和经历记录、来源、确认状态、档案版本。 |
| 岗位与个人跟进 | 来源 ID 或 URL、原始 JD、提取条件、获取时间；账号与岗位关系、入池、收藏、归档。 |
| 投递与沟通 | 申请状态、实际日期、备注、招呼语及变更前后值。 |
| 分析与任务 | 岗位和档案版本、分析依据与时间、任务阶段、成功结果和失败原因。 |
| 对话 | 账号 ID、岗位 ID、消息、原文引用，以及补充信息的使用范围。 |

### 失败时怎么处理

获取受阻时暂停并保留已有岗位，用户处理登录后继续或重试。模型失败时保留原文，支持重试分析或人工继续筛选。没有结果时显示真实数量和原因，不用示例填充。保存失败时不提示成功、不覆盖旧记录，保留输入供重试；重复点击不重复创建记录。

### 验收清单

- 能真实获取一批岗位并查看原始 JD 和来源；重复获取不覆盖收藏及投递记录。

- 简历提取先展示草稿。教育与项目分别进入对应模块，未确认条目不入档。

- 更新已有项目后保留原 ID、不增加重复项目；新简历未提及的旧经历不删除。

- 教育匹配能区分必备、优先与未知；985／211 未命中优先项不直接淘汰。

- 选中文字只附加引用、不立即发送；仅本次经历补充不影响长期档案。

- 搜索结果经人工选择才入池；取消收藏不移出；有投递历史的岗位移出后可归档恢复。

- 招呼语可编辑复制，生成和复制不发送、不修改状态；实际状态经用户确认保存。

- 刷新可恢复数据；账号切换不混用记录；保存失败和撤回可重试且不丢失旧记录。
