# InternPilot 开发交接说明

## 当前交付

本次同步在线第 7 版工作台，日期为 2026-10-21。页面和交互可以直接修改，不需要先换框架。

先阅读 [当前版本开发 PRD](PRD.md)。PRD 定义要开发的行为；当前代码仍是静态交互原型，尚未连接招聘平台、真实模型或后端数据库。示例任务和规则回复不能代替真实接入验收。

在线原型：https://internpilot-ui.valid-moose-4187.chatgpt.site

这份源码不包含原站托管配置、凭据或用户浏览器中的个人记录。GitHub 与原站没有自动部署关联。

## 运行与检查

在仓库根目录运行：

```sh
python3 -m http.server 8000 --directory dist
```

访问 http://localhost:8000 。停止服务时按 Ctrl+C。不需要安装前端依赖，也没有构建步骤。

有 Node.js 时运行：

```sh
node checks.cjs
node checks-auth.cjs
node checks-profile.cjs
```

共 119 项逻辑检查：85 项业务、16 项账号、1 项完整账号重载、17 项个人档案。检查使用 Node VM 和简化 DOM。教育卡片、材料核对、新增与更新以及教育匹配另已在浏览器中验证；这不代表真实平台或模型已集成。

## 代码入口

脚本按 `app.js → experience.js → job-pool.js → profile.js → auth.js` 加载。后加载脚本会覆盖部分基础函数，请保留顺序。`dist/` 在本项目中是直接维护的源文件目录。

| 文件 | 职责 |
|---|---|
| dist/index.html | 页面容器及脚本入口 |
| dist/style.css | 工作台、登录、岗位详情及个人档案样式 |
| dist/app.js | 基础状态、页面框架和示例岗位任务 |
| dist/experience.js | 选中文字提问、岗位助手、经历编辑、确认和撤回 |
| dist/job-pool.js | 搜索结果、入池、收藏、归档、手动添加和状态管理 |
| dist/profile.js | 教育背景、材料提取预览、用户指定新增或更新、来源与教育核对 |
| dist/auth.js | 两个演示账号、进入、退出、切换及本地账号记录 |

## 本轮新增档案逻辑

- “基本信息与求职意向”包含独立教育经历，每段保留学校、学历、状态、专业、学科、日期、院校标签和相关课程。
- 原始简历材料与确认后的教育、经历记录分别保存。当前接收粘贴文字、TXT 和 Markdown，不解析 PDF/Word。
- `extractMaterialLocally` 仅按本地文本标题整理草稿。真实开发时可替换为模型提取，但必须保留核对流程。
- 提取后逐条展示原文和编辑字段。用户选择新增、指定已有记录更新或跳过；只在确认后保存本条。
- 更新沿用原记录 ID。没有出现在新简历里的旧经历不删除；不自动合并，不把整个新简历覆盖成一套档案。
- 教育和经历保留原文片段及来源名称，支持查看、编辑、删除、撤回与历史版本。
- 985/211 仅对照岗位明确要求或优先项。未命中优先项不直接淘汰；未填写不等于不符合。

## 接入位置

以下函数是目前的交互入口，不代表现成后端接口。

| 当前入口 | 开发时接入 |
|---|---|
| startSearch、storeSearchResults | 真实岗位获取任务、进度、来源和结果，保留失败重试 |
| educationRequirements、educationAssessment | 从真实 JD 提取明确教育条件，保留原文和未知项 |
| matchDetail、baseMatchDetail | 模型匹配分析，提供岗位与个人事实证据及版本 |
| beginMaterialReview、extractMaterialLocally | 材料提取，结果进入现有待核对队列 |
| commitMaterialItem、saveEducation、commitExperience | 用户确认后保存档案，更新时保持原记录 ID |
| sendChat | 携带岗位 ID、引用和相关事实的真实对话 |
| regenerateGreeting | 以已确认事实生成招呼语，保留编辑和复制 |
| updateSaved、changePool、updateStatus | 持久化跟进、收藏、归档和实际投递记录 |

前端负责编辑和确认，后端负责工具任务、模型调用和数据库保存。模型密钥只放后端。本版演示账号选择不是身份认证，不提供真实多人访问保护。

岗位读取工具需要用户授权的招聘页面。可先在本机运行前端、后端和浏览器工具；遇到登录或验证就暂停并由用户处理。服务器不会自动继承用户本机的招聘平台登录状态。

## 必须保留的规则

1. 搜索结果不自动入池，用户单选或批选后保存；收藏搜索结果会同时入池，取消收藏不移出。
2. 岗位池只设“全部跟进／只看收藏／已归档”，有投递历史的岗位移出后归档并保留记录。
3. 未知信息保留待确认，明确到岗冲突不被能力相关性抵消，示例数值不是实际匹配门槛。
4. 选中文字只显示“向助手提问”，点击附到输入框而不发送，切换岗位清除未发送旧引用。
5. 个人事实写档前由用户核对；仅用于本次对话的补充不影响其他岗位和长期档案。
6. 生成、复制文案和打开链接都不等于实际投递。用户在原平台操作后确认状态、日期和备注。
7. 重抓岗位、更新档案和重新分析不覆盖用户已有的收藏、文案、日期或投递备注。
8. 写入失败保留原记录和可重试输入，重复提交不重复创建。撤回只恢复本次涉及字段。

## 协作方式

修改功能后运行三个检查脚本，并在浏览器中检查实际交互。技术实现以 PRD 的当前范围为准，原型中的演示按钮不构成额外开发要求。

在同一 GitHub 仓库通过分支和 Pull Request 协作；修改源码不会自动发布到现有在线站点。运行后端时需为前端配置可访问的接口地址，线上页面不会自动连接开发同学电脑上的 localhost。
