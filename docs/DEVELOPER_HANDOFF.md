# InternPilot 开发交接说明

## 1. 这个包可以怎么用

这是当前在线工作台的可编辑源代码，不是截图或设计文件。接手者可以保留页面和交互，在此基础上接入后端、模型和岗位获取工具。

对应在线原型：https://internpilot-ui.valid-moose-4187.chatgpt.site

代码基线：2026-10-20，在线第 6 版。
源代码提交：27edb8a0645fe6acad7049e0329c0c9a077abee6。

导出包保留当前版本的界面代码和逻辑检查；没有打包 Git 历史、托管配置、浏览器中的用户记录或任何登录凭据。它可独立开发、部署，不会自动修改原来的在线站点。

## 2. 本地打开

在解压后的项目根目录打开终端，执行：

```sh
python3 -m http.server 8000 --directory dist
```

浏览器访问：http://localhost:8000

停止：回到终端，按 Ctrl+C。无需安装前端依赖，也没有构建步骤。建议固定使用同一端口，浏览器本地记录与访问地址有关。

这条命令只启动静态网页，尚未启动任何真实采集或大模型功能。不要把能打开网页误认为已完成完整系统。

有 Node.js 时，可运行现有逻辑检查：

```sh
node checks.cjs
node checks-auth.cjs
```

当前有 85 项原有行为检查、16 项账号行为检查和 1 项完整账号重载检查通过。检查基于 Node VM 和简化 DOM，不等于浏览器端验收；还需补做真实浏览器操作与视觉验收。

## 3. 文件对应关系

| 文件 | 作用 | 接手时注意 |
|---|---|---|
| dist/index.html | 页面入口、脚本加载顺序 | 顺序为 app、experience、job-pool、auth |
| dist/style.css | 整体布局和全部页面样式 | 已有工作台、岗位详情、登录页等样式 |
| dist/app.js | 基础状态、工作台框架、演示任务、状态和文案操作 | 有样例数据和基础函数；部分函数被后续脚本替换 |
| dist/experience.js | 岗位文字选择提问、嵌入式助手、经历与能力档案 | 保存个人事实前需要确认 |
| dist/job-pool.js | 搜索结果、岗位池、收藏视图、手动添加、归档和撤回 | 这里定义了最终的岗位池行为 |
| dist/auth.js | 演示登录、退出、账号切换和本地记录分别保存 | 必须换成服务端身份认证后才是真实账号系统 |
| checks.cjs | 岗位池、档案、状态和异常恢复等逻辑检查 | 新增后端后应补充接口和集成检查 |
| checks-auth.cjs | 演示账号、迁移、退出、切换和恢复检查 | 不用于证明真实认证安全 |
| README.md | 当前原型功能与边界的完整说明 | 与本交接说明配合阅读 |

现阶段使用原生 HTML、CSS、JavaScript，没有使用 React/Vue，也没有现成后端。全局函数之间存在覆盖和依赖；修改前先核对脚本顺序。当前结构适合课程原型，后续可逐步拆分页面、状态和接口模块，不必为了接手先重写整套 UI。

## 4. 已有功能与待开发部分

| 功能 | 当前实际状态 | 接手者需要实现 |
|---|---|---|

| 匹配分析 | 示例岗位含预设说明和静态分数，未调用模型 | 用模型对照 JD 和个人档案，输出匹配点、缺口与原文依据 |

| 投递管理 | 人工标记状态、日期、备注，支持批量和撤回 | 服务端持久化、变更记录；不自动监测招聘平台状态 |
| 简历材料 | 示例文字及可编辑材料，不是文件解析服务 | 如需上传 PDF/DOCX，补充上传、解析、删除和错误反馈 |

## 5. 推荐先跑通的一条真实链路

目标是一个可演示的闭环：

用户设置求职条件 → 调用工具获取一批真实岗位 → 根据档案分析匹配点和缺口 → 用户选择入池或收藏 → 生成并编辑招呼语 → 用户去原平台完成投递 → 回来标记状态并保存。

先做以下四件事：

1. **验证一个招聘平台能否稳定获取。** 先用 5–10 个岗位验证，保留来源 URL、原始 JD 和获取时间；遇到登录、验证码或页面变化时停止并提示用户接管。不要先承诺支持所有招聘平台。
2. **做一条真实模型调用。** 输入一份 JD 和一份档案，输出结构化匹配点、未知项、缺口和对应证据。模型失败时保留原始岗位，不覆盖投递状态。
3. **把岗位池和投递记录写入数据库。** 刷新后可恢复；人工状态不被再次获取岗位覆盖。
4. **接回当前界面，完成端到端演示。** 最后再扩展多用户真实登录、文件解析、复杂排序等能力。若课程明确要求真实多人账号，身份认证应提前作为数据库接口的基础。

## 6. 实现层次与接口建议

前端工作台负责展示、交互和确认；后端负责存取、任务调度和模型调用；岗位获取工具负责与招聘网页交互；数据库保存用户档案、岗位和投递记录。

下面只是便于沟通的接口草案，目前代码没有这些接口：

| 接口示例 | 用途 |
|---|---|
| GET /api/me | 获取当前真实登录用户 |
| POST /api/auth/logout | 退出真实会话 |
| GET /api/profile | 读取个人档案 |
| PATCH /api/profile | 确认后更新个人档案 |
| POST /api/search-tasks | 创建岗位获取任务，返回 task_id |
| GET /api/search-tasks/{id} | 返回任务进度、异常或获取结果 |
| POST /api/jobs/{id}/match | 对照档案生成结构化匹配分析 |
| POST /api/chat | 带岗位和引用文字的对话 |
| POST /api/jobs/{id}/greeting | 根据已确认事实生成招呼语草稿 |
| GET /api/pool | 读取跟进、收藏或归档视图 |
| POST /api/pool | 人工添加岗位到池 |
| PATCH /api/pool/{id} | 收藏、移出或归档等操作 |
| PATCH /api/applications/{id} | 人工确认投递状态、日期和备注 |

账号注册、登录方式（如密码或第三方登录）需由开发者选择认证方案后定义接口。服务端必须从真实会话取得用户身份，不可信任前端随意传入的 user_id。模型密钥只留在后端。

### 与现有函数衔接

- startSearch / storeSearchResults：用真实任务结果替换 demoJobs；保留“获取不等于入池”。
- sendChat：替换规则式回复，继续传递 jobId、引用文字、本人确认的经历与材料。
- regenerateGreeting：替换成模型生成；保留用户编辑与复制，不自动改变投递状态。
- updateSaved / changePool / updateStatus：逐步接入后端写入；保留失败回滚和明确状态规则。
- commitExperience / saveProfile：接入档案更新接口，确认后再写入。
- auth.js：整体替换演示认证层，不能在现有逻辑上加个密码框就认为有了真实认证。

### 岗位获取工具如何接

当前网页是静态前端，不能仅靠页面中的一个 fetch 就等价于“控制用户已登录的招聘网页”。需要考虑平台接口权限、浏览器登录状态、跨域和网页变化。

课程项目可先让前端、后端和采集工具都在同学电脑上运行：用户在自己的招聘平台浏览器中登录，本地工具完成经授权的读取，后端返回标准岗位结构给前端。后续再讨论部署；服务器上的浏览器不能自动继承用户电脑上的登录状态。

导入岗位可以保留为测试与异常恢复入口，但项目目标仍包括真实自动获取，不应把演示数据或手工导入标注为“已实现自动获取”。

## 7. 需要保留的产品规则

1. 搜索结果不会全部自动进入岗位池，由用户明确选择保留。
2. 岗位池只有一个一级模块，内含“全部跟进 / 只看收藏 / 已归档”。
3. 收藏是重点标记；取消收藏不等于移出岗位池。
4. 城市、到岗天数、实习时长等硬条件单独判断。信息缺失表示待确认，不等于不符合；分数不决定能否入池。
5. 有投递历史的岗位移出后归档，保留历史；未投递岗位可以可撤回地移出。
6. 获取岗位、复制招呼语、生成分析，都不等于已经投递。实际投递状态由用户确认。
7. 岗位原文与助手在桌面网页中并排呈现；选中文字只出现“向助手提问”，先附到输入框，不立即发送。
8. 经历与能力属于个人档案的子模块；个人事实写入前确认。
9. 模型不得编造经历、熟练程度、量化结果或岗位要求。岗位原文是待分析的数据，不能覆盖系统规则或触发未经确认的操作。
10. 面向所有实习方向。目前示例岗位偏运营，但产品范围不因此限制为运营。
11. 不做简历撰写、自动发送招呼语、自动投递和 HR 回复监测。

## 8. 可用于验收的场景

- 真实获取一批岗位，能回到来源核查，显示获取时间和失败原因。
- 再次获取同一岗位不重复创建跟进记录，不覆盖用户备注、文案或状态。
- 缺少到岗要求或个人证据时，结果明确显示待确认。
- 选择其中几个岗位入池，全部跟进、只看收藏、归档三视图一致。
- 选中一句 JD 提问时，助手使用的是该岗位和这句引用。
- 招呼语只采用档案中可追溯的事实，用户可编辑、复制，不发生真实自动发送。
- 标记已投递，刷新后记录仍在；移出该岗位时保留投递历史。
- 获取失败或模型超时时，可以重试或人工继续，已有档案和状态不丢失。
- 真实多用户版需验证不同账号不能读取或修改彼此记录。

## 9. 协作和部署

建议把解压后的代码放到你们共同的 GitHub 仓库，由同学提交代码，你负责确认页面、流程和验收场景。源码压缩包用于起步，持续协作用同一个仓库管理版本。

这个包不包含原站的托管身份。上传到新的托管服务会得到新的链接；要覆盖当前在线站点，需要回到原站编辑和发布流程，不能只把代码改在自己电脑上就期待旧链接更新。

如后端运行在同学电脑上，线上网页也不会自动连上 localhost。课程阶段先本地端到端跑通；上线时再共同部署后端、数据库和可访问的接口地址。
